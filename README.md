# 전체 구조 개요

이 문서는 코드를 유지보수하는 사람이 **전체 그림을 빠르게 잡기 위한** 자료입니다.

## 레이어

```
┌──────────────────────────────────────────────┐
│  app/     메인 폼 · 진입점 · 프로바이더 선택   │
├──────────────────────────────────────────────┤
│  modules/ 모듈별 화면 + 업무 로직              │
│           (item, partner, inventory, quote,    │
│            shipment, history)                  │
├──────────────────────────────────────────────┤
│  core/    엔티티 + 데이터 접근 인터페이스      │
│           (IItemRepository 등) + 프로바이더    │
└──────────────────────────────────────────────┘
```

각 모듈은 `core`의 **인터페이스에만 의존**합니다. 모듈이 Firebird인지
Memory인지 알 필요가 없습니다.

## 데이터 접근 방식

데이터 접근은 인터페이스(예: `IItemRepository`)로 추상화됩니다.
같은 인터페이스에 대해 두 가지 구현이 존재합니다.

| 프로바이더 | 설명 | 사용 시점 |
|-----------|------|-----------|
| Memory | 인메모리 리스트 + 샘플 데이터 | 기본값. DB 미설치 환경 |
| Firebird | FireDAC로 Firebird 연결 | `app.ini`에서 전환 |

앱 시작 시 `app/`의 초기화 코드가 `app.ini`의 `[Data] Provider` 값을 읽어
프로바이더를 하나 생성하고, 모듈들에 인터페이스로 주입합니다.
Firebird 연결이 실패하면 Memory로 폴백합니다.

### 이 구조의 이유
- **DB 없이 실행 가능**: 설치 부담 없이 즉시 구동·데모.
- **교체 용이**: 나중에 다른 DB로 바꿔도 모듈 코드는 그대로.
- **테스트 용이**: Memory 프로바이더로 로직만 빠르게 검증.

## 모듈 간 의존

```
item ─────┐
          ├──► inventory ──► shipment
partner ──┤                     │
          └──► quote            │
                                ▼
                             history (읽기 전용 조회)
```

- `item`, `partner`는 마스터(토대). 먼저 완성되어야 합니다.
- `inventory`는 `item`에 의존(품목별 수량).
- `quote`는 `item`+`partner`에 의존.
- `shipment`는 출고 시 `inventory` 수량을 차감.
- `history`는 모든 변동을 읽어 보여주는 조회 전용.

## 어디를 고칠 것인가 (빠른 안내)

| 하고 싶은 일 | 볼 위치 |
|-------------|---------|
| 품목 필드 추가 | `core`의 품목 엔티티 → 각 프로바이더 → item 화면 |
| DB 접속정보 변경 | `config/app.ini` |
| 새 DB로 교체 | `core`에 새 프로바이더 구현 추가, `app/` 초기화에서 분기 |
| 재고 차감 규칙 변경 | `modules/shipment` 로직 → `inventory` 갱신 지점 |
